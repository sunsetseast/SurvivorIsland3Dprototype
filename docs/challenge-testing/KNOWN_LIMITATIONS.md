# Known limitations

- Physical iPhone 17 Pro Max Safari and the live Replit preview were **not tested**. Tests use actual browser touch events and software WebGL in Chromium, with mobile viewport emulation. Existing mobile-control CI also exercises WebKit; that does not certify the complete new hub on Safari hardware.
- The current hosted project's checkout, Run command, route and application entry point cannot be established from repository files. `.replit` names a `Project` workflow but does not define its command. No hosted settings were changed. A read-only app-title search before the user's prohibition did not identify the target; no further Replit access was made. The supported automatic entry uses Vite **development** mode. A production-served preview must use its existing development Run workflow to see the hub; this PR does not enable it in production.
- GitHub does not automatically synchronize a separate hosted project. The build/revision footer and **Challenge Hub v1** marker help identify the running version, but Git branch sync still depends on that project's existing interface. Draft work is on `feat/challenge-testing-hub`, not main.
- Stillwater is the existing PR #24 rehearsal: current five rendered participants, eight available stations, 90-second ranking/tie rule, no immunity award or permanent season record. Mechanics and opponent behavior are unchanged. The three other configurations remain environment previews.
- The hub works in portrait and landscape; existing competition presentation is intended for landscape. Safe-area CSS and 44px targets were checked with emulated dimensions, not physical notch/home-indicator hardware.
- Resource counts are representative frames, not measured physical-device FPS or VRAM. Test advancement holds the render loop and renders selected frames to keep software-WebGL QA bounded. Resident texture bytes and hardware throughput are not measured.
- After menu teardown the old Three.js texture info counter can read 1 even though its WebGL context is destroyed. The test separately verifies context loss, zero owned resources/geometries/canvases and zero active scenes; it does not report this stale counter as live GPU memory.
- The original singleton camp provider/identities remain in memory, including cold starts, as in the existing architecture. Testing creates only a temporary travel/session scope; it does not create another camp/social runtime. In-memory preservation is tested; this PR adds no new persistence system.
- Existing Vite warnings about large chunks and a module imported both statically/dynamically remain. No dependencies, launch settings or thresholds were changed.
